# Информационная археология

## Правило

**Рабочее дерево — один снимок одной ветки. Факт о репозитории добывается из
`--all`, факт о «едет ли к проду» — из release/master, факт о доке — из
machine-readable источника. Каждое правило ниже выведено из реальной ошибки
разведки 02.09.2026 (поллер GBS в delivery не увидели с отставшего чекаута).**

## 1. Чекаут — не источник истины

Реальная ошибка: разведка delivery-service честно отчиталась «Яндекса и
поллеров статусов нет» — чекаут стоял на майской ветке, поллер жил в
августовских release-ветках.

- Первым делом: `git branch --show-current` и `git log -1 --date=short` —
  насколько отстало дерево; если можно — `git fetch` перед выводами.
- Искать по всем веткам, не по дереву: `git log --all`,
  `git grep <pattern> <ref> -- src`, `git branch -a`.
- Читать код с веток, не переключая дерево: `git show <ref>:<path>`.
  Чужие рабочие деревья и корневые чекауты не переключать никогда.

## 2. Ось автора

«Поллер писала Марьям» — это уже ключ. Сначала карта авторов, потом их файлы:

```bash
git log --all --format='%an' | sort | uniq -c | sort -rn | head   # кто тут есть
git log --all --author="<часть имени>" --oneline --date=short --format='%h %ad %s' | head -25
git log --all --format='%an' -- <path> | sort | uniq -c           # чей файл
```

## 3. Мерж-состояние — фактом, не заголовком

Реальная ошибка: свежие мержи Марьям в master («config-for-courier-delivery»)
выглядели как искомый поллер — оказались однострочным конфиг-флагом; сам поллер
до master не доехал.

- `git merge-base --is-ancestor <ref> origin/master && echo IN || echo NOT`
- `git branch -r --contains <ref>` — где фича реально едет
  (release/* и staging = едет к проду, даже если master пуст).
- Однострочный флаг в master — часто видимый кончик фичи из release-ветки:
  греп по имени флага находит проводку. Поведение системы меняют данными, а не
  кодом сервиса — см. скилл code-config-driven.

## 4. Отрицательный результат дороже положительного

Реальные ошибки: «нет консюмера топика» было бы недоказано грепом только по
`src` одного сервиса (консюмер мог сидеть в helm/compose/харнессе); «оба
сервиса знают про курьеров» — под двадцать hits на сервис, все до единого
ложные (`MESSAGING_DRIVER` ловился паттерном driver).

- Полнорепный греп: все расширения, исключить только node_modules/dist/.git;
  для утверждения о ветке — грепать по ref, не по дереву.
- Hits читать глазами; счётчик совпадений аргументом не является.
- В отчёте различать три разных «нет»: нет в дереве · нет в репе (все ветки) ·
  нет нигде (репа + доки). Писать, которое именно доказано и чем.

## 5. Дока внешней системы — machine-readable сначала

Реальная ошибка: страницы доки роутера 302-или на лендинг, WebFetch резал их по
длине; полный перечень эндпоинтов за минуту дала OpenAPI-спека, лежащая за
Redoc-страницей.

- Искать в корне доки `llms.txt` / `llms-full.txt`; у Diplodoc-сайтов у каждой
  страницы есть `.md`-версия — качать её, не HTML.
- За Redoc-страницей лежит спека: в HTML будет `Redoc.init('./openapi.yaml')` —
  скачать и распарсить (55 путей из yaml надёжнее 55 страниц). Того же класса:
  swagger.json, postman-коллекция.
- `curl -sL --compressed` (иначе прилетает gzip-бинарь). Мёртвый URL → лечь на
  web-поиск нового корня доки, а не сдаваться на 302.

## 6. Выдача

- Формат грепов — компактный `L<строка>:` из CLAUDE.md (строки не резать,
  абсолютные пути в каждой строке не печатать).
- Каждое утверждение — с ref и file:line; для «влито/не влито» — команда,
  которой это проверено.
- Субагенту-разведчику давать context-pack и явно требовать этот протокол
  и секцию «## Трение» в отчёте.
